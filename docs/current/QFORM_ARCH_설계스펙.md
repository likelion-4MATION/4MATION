# Q-Form AS-BUILT 설계

> rev.8 현행 요약 · 2026-08-30 재구성
> 구현: `chatbot/qform_*.py`, `chatbot/attachments.py`, `web/service.py`

이 문서는 과거 스프린트 추기 로그를 반복하지 않고 현재 코드가 보장하는 Q-Form 계약을
설명합니다.

## 1. 목적과 경계

Q-Form은 질문을 특정 조합 행으로 좁혀 필요한 서류·정보를 고르는 결정론 계층입니다. 답변을
새로 계산하거나 개인의 자격·한도·감면 여부를 판정하지 않습니다.

현재 지원 범위:

| 업무 | 기본 상태 | 조합 테이블 |
|---|---|---:|
| 착오송금 반환 신청 | 기본 활성 | 14행 |
| 예금보험금 안내 | 관리자 토글 `msdr+dpin`에서 활성 | 9행 |

기본 `QFORM_SCOPE`는 `msdr`입니다. 예금보험금 Q-Form은 데이터와 코드가 있으나 기본 운영
범위에는 포함하지 않습니다.

## 2. 슬롯

정본 슬롯은 다음 5개입니다.

| 슬롯 | 의미 | 예시 |
|---|---|---|
| `party` | 업무 방향·역할 | 송금인, 수취인 |
| `sub_task` | 세부 용건 | 반환신청, 신청철회, 이의제기, 보험금신청 |
| `qualification` | 신청 자격 | 본인, 대리인 |
| `subject` | 실제 대상 주체 | 법인, 미성년자, 군복무자, 사망 예금자 |
| `method` | 접수 수단 | 온라인, 방문, 우편, 이메일, 팩스 |

예금보험금 조합에서는 `party`를 사용하지 않습니다. 실제 9행이 모두 빈 값이며, 쓰지 않는 축을
형식상 노출하면 잘못된 추출값이 들어앉을 수 있기 때문입니다.

`outcome`은 입력 슬롯이 아니라 조합 행의 결과 유형입니다.

- `정보`
- `서류`
- `서류;정보`

## 3. 처리 흐름

```text
질의
  → BF 분류
  → scope 확인
  → 슬롯 추출
  → 조합 테이블 survivors 계산
  → 필요한 경우 qualification/subject 되묻기
  → 조합 결과를 답변·첨부 후단 필터에 전달
  → 후속 추천과 메모리 패널 생성
```

모든 질의는 추출기를 통과할 수 있지만, 범위 밖 업무는 빈 슬롯으로 안전하게 종료합니다.

## 4. 되묻기 규칙

되묻기는 다음 조건을 모두 만족할 때만 발생합니다.

1. 업무가 Q-Form scope 안에 있음
2. `sub_task`가 식별됨
3. 남은 조합 행이 한 행으로 좁혀지지 않음
4. 아직 묻지 않은 `qualification` 또는 `subject` 축이 분기를 실제로 줄임
5. `MAX_ASK_TURNS` 미만

`sub_task=None`이면 되묻지 않습니다. 짧은 정의형·일반 질문이 잘못된 폼으로 진입하는 것을
막기 위한 경계입니다.

되묻기 방식:

| 모드 | 동작 | LLM 호출 |
|---|---|---:|
| `template` | `qform_prompts.csv` 고정 문구 | 0 |
| `llm` | 허용 옵션을 바탕으로 문구 생성 | 되묻기당 1 |

되묻기 턴에서는 RAG 답변 생성을 호출하지 않습니다. 상한에 닿거나 사용자가 바로 답변을
선택하면 현재 슬롯으로 답변 단계에 진입합니다.

## 5. 조합 테이블

### 착오송금

- 파일: `crawler/data/qform_combos_msdr.csv`
- 행: 14
- 역할: 반환신청·철회·계약해제·계좌변경·대리인변경·이의제기·수수료환급 조합
- 근거 연결: `source_doc_id`, `evidence_chunks_v0`

### 예금보험금

- 파일: `crawler/data/qform_combos_dpin.csv`
- 행: 9
- 역할: 제도안내, 본인·대리인, 특수 주체별 보험금 신청 조합
- 근거 연결: `evidence_chunks_v0`, `evidence_spans`, `evidence_span_hits`
- 머리의 `#` 주석행은 CSV 데이터가 아니며 로더가 건너뜀

조합 행은 허용값을 `;`로 여러 개 가질 수 있습니다. 슬롯과 행이 교집합을 가지면 생존합니다.

## 6. 첨부 후단 필터

검색이 찾은 문서의 첨부를 먼저 수집한 뒤 Q-Form 조합으로 좁힙니다.

안전 계약:

- 필터는 첨부를 추가하지 않고 기존 결과의 부분집합만 반환
- `qform=None` 또는 `sub_task=None`이면 무손실 통과
- 해당 업무 테이블에 없는 `sub_task`면 무손실 통과
- 필터 결과가 0개면 원본 첨부를 보존해 전멸 방지
- 한 업무의 조합 테이블은 그 업무 첨부에만 적용

## 7. 슬롯 기억과 멀티턴

기본 설정:

| 설정 | 기본값 | 허용값 |
|---|---:|---|
| `SLOT_CARRYOVER` | `true` | bool |
| `CARRYOVER_TTL` | 3 | 1~5 |
| `CARRYOVER_SCOPE` | `bf_match` | `bf_match`, `global`, `off` |
| `MAX_ASK_TURNS` | 2 | 1~3 |
| `QFORM_SCOPE` | `msdr` | `msdr`, `msdr+dpin` |
| `MAX_QUEUE` | 3 | 0~5 |
| `PANEL_EXPIRED` | `gray` | `gray`, `drop` |

`bf_match`는 업무가 같을 때만 슬롯을 이월합니다. 새 질의에서 명시적으로 추출한 값이 기억값보다
우선하며, TTL이 지난 값은 답변에 적용하지 않습니다. 라우터가 짧은 후속질의를 다른 업무로
과분류하더라도 명시 업무 키워드가 없고 직전 업무에서 실제 슬롯이 추출되면 직전 문맥을 유지합니다.
무관 질의는 슬롯이 추출되지 않고, 명시 업무 전환은 키워드 근거가 있으므로 이 보정을 타지 않습니다.

## 8. 메모리 패널

사용자 화면은 메모리를 세 구역으로 나눕니다.

| 구역 | 내용 |
|---|---|
| 적용 중 | 현재 답변과 첨부 필터에 쓰는 슬롯 |
| 만료 | TTL이 지나 적용하지 않는 슬롯 |
| 대기 중인 용건 | 한 발화에서 발견한 추가 `sub_task` |

지원 액션:

- 슬롯 수정
- 슬롯 지우기
- 특정 슬롯 건너뛰기
- 대기 용건 삭제·순서 이동
- 현재 조건으로 즉시 답변

패널 조작 자체는 LLM 답변을 호출하지 않습니다. 답변 액션을 명시했을 때만 생성 경로로 갑니다.

## 9. 다중 의도

질의를 절로 나눈 뒤 서로 다른 `sub_task`가 2개 이상이면 현재 용건 외 나머지를
`unit_queue`에 넣습니다. 업무 자체가 여러 개면 OOS 오케스트레이터의 절 큐와 함께 순차
처리합니다.

`MAX_QUEUE=0`이면 Q-Form 대기 용건 큐를 사용하지 않습니다.

## 10. 후속 추천

되묻기는 현재 조합을 좁히고, 후속 추천은 다음 탐색 방향을 제시합니다. 역할을 겹치지 않게
유지합니다.

- 되묻기 축: `qualification`, `subject`
- 후속 추천 축: `sub_task`, `method`, `party`

후속 추천 클릭은 새 자연어 질의를 만들지 않고 슬롯 액션으로 처리합니다. 이후 재답변 때
모든 확정 슬롯은 아래의 공통 검색 직렬화 규칙을 따릅니다.

### 검색 조건 반영

사용자 웹의 `Q-Form 검색 조건 반영`은 기본 ON입니다. 원 질의는 라우팅과 답변 생성에
그대로 사용하고, 검색기에만 고정 순서의 구조화 블록을 덧붙입니다.

```text
사용자 원 질의

[QFORM]
party: 송금인
sub_task: 반환신청
qualification: 대리인
subject: 미성년자
```

- 값이 없는 필드는 생략
- 신규 추출값과 유효한 이월값을 함께 반영
- OFF면 검색 질의도 원 질의와 완전히 동일
- 원 질의와 실제 검색 질의를 이벤트·응답 메타·트레이스에 각각 기록
- 확장 검색문을 생성 프롬프트의 `[질문]`에 넣지 않음

## 11. 판정하지 않는 것

다음은 Q-Form의 현재 범위가 아닙니다.

- 예금자보호 한도 개인별 계산
- 은닉재산 포상금 계산
- 채무조정 감면·자격 판정
- 개인정보가 필요한 개별 심사
- 미래 사건에 따라 갈리는 상태기계형 경로 판정

이 경우 문서의 일반 규칙과 상담 범위를 안내할 수 있지만 개인 결론을 계산하지 않습니다.

## 13. 변경 규칙

- 슬롯 허용값을 바꾸면 추출기·조합 CSV·프롬프트·메모리 패널을 함께 확인
- `QFORM_SCOPE` 기본값을 바꾸면 웹 기본 설정과 회귀 테스트도 함께 변경
- 조합 행을 바꾸면 근거 문서·청크·span을 검토
- 검색 조건 직렬화 형식이나 기본값을 바꾸면 원문/검색문 분리 테스트를 함께 변경
- 개별 사용자 자격을 판정하는 로직을 조합 테이블에 넣지 않음
