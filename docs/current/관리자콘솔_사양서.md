# KDIC 챗봇 관리자 콘솔 AS-BUILT 사양

> 대상: 비전공자 운영 관리자
> 기준: `main` · 2026-08-30
> 구현: `admin/` 전체와 `crawler/rag.py`, `crawler/chunk.py`, `chatbot/qform_config.py`

## 1. 설계 원칙

### 원본 코드와 운영값 분리

관리자 변경값은 `admin/data/admin_config.json`에 저장하고, `settings.apply_runtime()`이 Python
모듈 상수에 주입합니다. 청킹 설정은 재빌드가 성공할 때까지 `pending`에 격리합니다.

### 측정하지 않은 숫자를 만들지 않음

- 같은 코퍼스·모델·판정 기준의 실측만 직접 비교
- 측정값이 없으면 `미측정`
- 앵커 hit와 chunk-id hit는 별도 계열
- 여러 검색 축을 동시에 바꾼 조합의 성능을 단순 곱으로 추정하지 않음
- 응답시간·비용 계산에는 `측정`, `계산`, `추정` 등급 표시

### 실제 서비스와 대시보드 정합성

대시보드는 `crawler/data/chunks.jsonl`, 검색기는 `crawler/data/index/chunk_meta.jsonl`을 읽습니다.
행 수가 다르면 같은 기준선이 아니므로 성능 비교를 차단하고 재빌드가 필요합니다.

## 4. 프리셋과 기준선

검색 프리셋은 `RRF_ALPHA`, `RRF_K`, `BF_BOOST`, `FACET_BOOST`, `BF_DOC_CAP`을 한 세트로
전개합니다.

| 프리셋 | 값 요약 |
|---|---|
| 정확도 우선 | 0.65, 4, 0.06, 0.05, 5 |
| 균형 | 0.65, 4, 0.03, 0.05, 5 |
| 다양성 우선 | 0.65, 2, 0.03, 0.10, 3 |

`registry.GOLDEN`의 앵커 hit@5 0.9081과 관련 기준선은 181청크 시점의 코드 상수입니다. 그
수치를 만든 실험 리포트는 essential 저장소에 없으므로 현재 독립 감사 자료로 취급하지 않습니다.
새 코퍼스에서는 관리자 재검증 결과를 우선합니다.

## 5. 저장과 반영

| 상태 | 의미 |
|---|---|
| 기본값 | 코드 레지스트리 값 |
| `override` | 현재 서비스에 적용하기로 확정한 값 |
| `pending` | 재빌드 성공을 기다리는 청킹 값 |
| 이력 | 저장·되돌리기 감사 기록 |
| 측정 이력 | 평가 결과와 당시 설정 스냅샷 |

사용자 챗봇과 관리자는 별도 프로세스입니다. `web/service.py`는 관리자 설정 파일의 교체를
생성 요청 전에 확인하고 런타임 설정을 다시 적용합니다. 청킹 설정은 재빌드 후 반영됩니다.

## 6. 작업 상태기계

| 작업 | 단계 | 실패 시 |
|---|---|---|
| `verify` | 인덱스 확인 → Q-Form 확인 → 평가 | 읽기 전용, 복원 불필요 |
| `eval` | 백업 → 샌드박스 빌드 → Q-Form 확인 → 평가 → 삭제·복원 | 백업 복원 |
| `rebuild` | 백업 → 서비스 빌드 → Q-Form 확인 → 평가 | 백업 복원 |
| `files` | parsed 백업 → 첨부 다운로드 → 연결 | parsed 복원 |
| `chain` | 변경 판정 → eval → 승인 대기 → rebuild → verify | 단계별 복원 |
| `recrawl` | 라이브 수집 → rebuild → verify | 백업 복원 |

청킹 값이 같고 dirty 깃발이 없으면 `chain`은 재검증만 합니다. 청킹 값이 다르거나 첨부 변경으로
dirty이면 샌드박스 평가와 재빌드를 수행합니다.

작업 판정 대기는 프로세스 메모리의 이벤트를 사용합니다. 대기 중 서버를 재시작하면 이어서
진행할 수 없고 새 작업을 시작해야 합니다.

## 7. 지표 계약

### 정확도

- 정본: 앵커텍스트 hit@k
- 앵커 미보유 문항: 분모 제외
- chunk-id hit: 감사용 별도 값
- `k`가 달라지면 서로 다른 hit@k이므로 단순 변화율을 내지 않음

### Q-Form 검색 반영

평가·재검증은 챗봇과 같은 Q-Form 경로로 검색합니다. 문항 슬롯은 평가셋의
`business_function`을 넘겨 `chatbot/qform_extract.extract()`로 뽑습니다(LLM 호출 0).
`QFORM_RETRIEVAL_MODE`에 따라 `field_value`는 검색문을 `[QFORM]` 블록으로 확장하고,
`metadata_soft`는 `search(qform=…)`로 청크 `qform_meta` 가산을 겁니다.

- 대조군: **슬롯이 잡힌 문항만** Q-Form 없이 한 번 더 검색해 `hit@1`·`hit@5`·`mrr@10`의
  차이를 냅니다. 슬롯이 없는 문항은 두 경로의 검색 입력이 같아 결과도 같으므로 분모에서
  뺍니다 — 전체 지표에 섞으면 효과가 희석돼 0으로 보입니다.
- `Q-Form 확인` 단계는 인덱스 청크의 태깅 현황(`keyed`/`tagged`)을 셉니다. `keyed=0`은
  태깅 이전 산출물이라 재청킹으로 해결되고, `keyed>0 tagged=0`은 조합표
  (`crawler/data/qform_combos_*.csv`) 문제라 재청킹해도 그대로입니다.
- 설정이 켜져 있어도 청크 태깅이나 가산치가 없으면 검색은 순수 hybrid와 같습니다.
  이 상태는 `/api/dashboard`의 `qform.effective=false`와 실행 전 경고로 드러냅니다.

### 속도·비용

실서비스 로그가 아니라 설정과 과거 경로 측정값을 이용한 계산·추정입니다. 실제 로그 저장소가
붙으면 `metrics.py`를 교체해야 합니다.

### 최고·직전·변경 후

정확도는 최대, 비용·응답시간·콜 수는 최소를 항목별로 선택합니다. 서로 다른 시점의 최적값을
하나의 “최고 설정”으로 묶지 않습니다.

## 8. 첨부 계약

현재 `crawler/data/doc_attachments.json`에는 6개 문서의 첨부 엔트리 46건이 있습니다.
실파일은 `crawler/data/files/`에 있으며 Git 비추적입니다.

- 표시명 수정·숨김: 오버레이
- 교체: 원본 유지, 관리자 업로드 파일로 대체
- 교체 취소: 오버레이 제거
- 외부 링크: `http(s)`만 허용
- 업로드: 허용 확장자, 최대 30MB
- 경로: 허용 저장소 밖으로 나가면 거부

첨부 실파일 재수집은 `pipeline.py`가 하지 않습니다. `files` 작업이
`fetch_attachments.py`와 `link_files.py`를 호출합니다. 이후 청크 메타 반영을 위해 재빌드가
필요합니다.

## 9. OOS와 오류 신고

OOS 안내처는 게시·활성·링크 정상·트리거 검증을 통과한 행만 노출합니다. 오류 신고는 SQLite에
개인정보 마스킹 후 30일 보관합니다.

상세는 [OOS 운영 가이드](./OOS_구현_운영가이드.md)를 봅니다.

## 10. 최신성 가드 배선 상태

구현됨:

- 가드 CRUD·상태 변경·삭제
- 내용 검증
- 프롬프트 블록 생성
- 숫자 화이트리스트 계산
- 미리보기와 통계
- `chatbot/chain.py`에서 승인 가드 매칭
- 생성 프롬프트 주입
- `answer_checks.py`에 허용 수치 전달
- 실제 답변 발동 카운트 기록

승인되었고 적용 시작일·종료일 안에 있는 가드만 질문·검색 컨텍스트·업무로 매칭합니다.
매칭된 사실은 코퍼스를 수정하지 않고 `[관리자 정정 사실]` 블록으로 생성 요청에 추가합니다.
`block` 유형은 생성 프롬프트에서 답변 보류를 지시하는 방식이며 별도 하드 차단 응답은 아닙니다.

## 12. 보안과 운영 제약

- 인증이 없으므로 외부 공개 금지
- 관리자 설정의 사용자 프로세스 자동 전파 없음
- 런타임 SQLite·설정·인덱스는 Git 비추적
- 업로드 용량·백업 정책은 별도 운영 필요
- fp32 라우터와 임베딩 동시 로드 시 메모리 약 4.8GB
- 라우터 MSP는 OOS 신호로 사용 금지
- 삭제된 과거 실험 리포트를 현재 근거로 링크하지 않음

## 13. 변경 체크리스트

- 파라미터 추가 시 `registry`, `settings.apply_runtime`, UI를 함께 변경
- 청킹 설정 추가 시 pending·재빌드·복원 경로 포함
- 평가 판정 변경 시 관리자 지표명과 비교 가능성 함께 검토
- 첨부 스키마 변경 시 크롤러·관리자·챗봇 후단 필터 함께 검토
- OOS 데이터 변경 시 게시 검증과 개인정보 마스킹 회귀
- 최신성 가드 변경 시 생성 프롬프트와 숫자 허용 목록 회귀 테스트 동시 확인
