# OOS 구현·운영 가이드

> 기준: 2026-10-12 · 코드: `chatbot/orchestrator.py`, `chatbot/oos_policy.py`,
> `admin/oos_store.py`

## 적용 범위

새 사용자 입력은 보수적으로 절 단위로 나뉩니다. 각 절은 기존 6업무 라우터를 먼저 통과하고,
업무로 판정된 절만 Q-Form과 업무 고정 RAG로 들어갑니다. 비업무 절은 OOS 정책으로 처리합니다.
한 입력에 절이 여러 개면 뒤 절은 세션 `unit_queue`에 순서대로 보관합니다.

```text
사용자 입력
  → 절 분리
  → 각 절 6업무 라우팅
  ├─ BF 판정 → Q-Form → BF 고정 RAG
  └─ 비-BF   → OOS 정책
                BOT_FEEDBACK / REFERRAL / CASUAL / FAR_OOS / PHONE_GUIDE
```

이 계층은 라우터 임계값 자체를 바꾸지 않습니다. `chatbot/router_adapter.py`가 현재 라우터의
결과를 그대로 소비합니다.

## OOS 액션

우선순위는 다음과 같습니다.

| 액션 | 조건 | 응답 |
|---|---|---|
| `BOT_FEEDBACK` | 챗봇 답변 대상 + 오류·틀림 신호 | 오류 신고 저장과 접수 안내 |
| `REFERRAL` | 게시 레지스트리의 트리거와 정확히 일치 | 검증된 기관·링크 안내 |
| `CASUAL` | 짧은 인사·감사·작별 | 고정 일상 응답 |
| `FAR_OOS` | 날씨·요리·스포츠 등 명백한 원거리 소관 밖 | 서비스 범위 고정 안내 |
| `PHONE_GUIDE` | 금융 인접·불확실·분류 실패 | 게시된 유선 상담 정보 또는 정보 없음 안내 |

조금이라도 불확실하면 `PHONE_GUIDE`로 닫습니다. `REFERRAL`은 게시된 행의 `row_id`가 있을
때만 유효합니다.

## 안전 규칙

- 6업무 라우터에서 BF가 나오면 OOS가 덮어쓰지 않습니다.
- OOS 경로에서는 RAG 검색과 답변 생성을 호출하지 않습니다.
- 기관명·URL·전화번호·운영시간은 게시·활성·검증 완료된 운영 데이터만 사용합니다.
- 원거리 OOS 응답에는 임의의 유선 상담 정보를 붙이지 않습니다.
- 정책 LLM 응답이 파싱 실패·시간초과·허용값 위반이면 `PHONE_GUIDE`로 폴백합니다.
- 운영 데이터가 없으면 값을 창작하지 않고 “게시된 정보 없음”으로 안내합니다.

## 운영 데이터

관리자 콘솔의 ⑧ OOS 안내처에서 타기관 안내와 유선 상담 정보를 관리합니다.

### 안내처 게시 조건

1. 필수 필드 존재
2. 정상 예시와 반례 미리보기 통과
3. 게시 행끼리 트리거 충돌 없음
4. 상태 `published`
5. 활성 상태
6. 링크 상태 `정상`

초기 데이터에는 실제 기관명·전화번호를 임의로 넣지 않습니다. 관리자가 공식 근거로 확인한 뒤
게시해야 사용자에게 노출됩니다.

Git에 포함된 `admin/data/oos.sqlite3`(2026-09-01 커밋)에는 이 절차로 게시한 타기관 안내처
2건(HUG 전세보증금반환보증, 금융감독원 분쟁조정·민원)이 들어 있고 유선 상담 정보는 비어
있습니다. 이 파일을 다룰 때의 주의점은 [RUNBOOK §9](./RUNBOOK.md#9-알려진-제약)를 봅니다.

## 오류 신고

오류 신고는 사용자 화면의 신고 액션 또는 자연어 오류 신호에서 생성됩니다.

- 저장소: `admin/data/oos.sqlite3`
- 원본 시각: UTC
- 관리자 화면: 한국시간 표시
- 보관기간: 생성 후 30일
- 저장 전 마스킹: 주민번호, 카드번호, 전화번호, 계좌번호, 이메일, 인증번호, 비밀번호
- 비밀키 계열 필드: 저장 대상에서 제외

관리자는 ⑨ 오류 신고함에서 상태, 담당자, 메모와 중복 그룹을 관리합니다.

## 실행

관리자와 사용자 서버 실행은 [RUNBOOK §2](./RUNBOOK.md#2-서비스-실행)를 따릅니다.

## 운영 점검

1. 안내처를 초안으로 저장합니다.
2. 정상 예시와 반례 미리보기를 확인합니다.
3. 공식 URL을 직접 확인합니다.
4. 링크 상태 `정상`, 상태 `published`, 활성을 설정합니다.
5. 사용자 챗봇에서 정상 예시로 고정 응답만 노출되는지 확인합니다.
6. 사용자 화면 신고와 자연어 오류 신고를 각각 생성합니다.
7. 신고함에서 마스킹·검색 근거·라우팅 기록·삭제 시각을 확인합니다.

API 생존 확인 명령은 [RUNBOOK §8](./RUNBOOK.md#8-oos-운영-확인)에 있습니다.

## 알려진 경계

- 현재 6업무 라우터는 소관 밖 질문을 BF로 과다 통과시킬 수 있습니다. BF로 통과한 절은 OOS가
  다시 분류하지 않으므로 이 문제는 별도 라우터 개선 대상입니다.
- 관리자 최신성 가드는 OOS와 별개이며, 소관 내 RAG 답변 생성 경로에서만 조건부 적용됩니다.
